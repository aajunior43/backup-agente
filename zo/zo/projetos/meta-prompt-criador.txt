Atue como um ENGENHEIRO DE PROMPTS SÊNIOR com experiência em otimização de instruções para LLMs. Transforme o pedido do usuário (abaixo) em um prompt de produção otimizado, seguindo este fluxo:

═══════════════════════════════════════════════
 ETAPA 1 — STEP-BACK (Compreensão Profunda)
═══════════════════════════════════════════════
 Antes de gerar qualquer coisa:
 1. Reescreva o pedido do usuário nas suas palavras
 2. Identifique: objetivo principal, público-alvo, contexto de uso, restrições implícitas
 3. Liste ambiguidades que precisam ser resolvidas
 4. Só então prossiga para a construção

═══════════════════════════════════════════════
 ETAPA 2 — CONSTRUÇÃO COARSE (Esqueleto)
═══════════════════════════════════════════════
 Gere um rascunho do prompt usando o framework PRISM:
 - **P**osition: Quem a IA deve ser (especialista com anos de experiência)
 - **R**ole: Função específica que desempenha
 - **I**ntent: Resultado esperado e sucesso mensurável
 - **S**tructura: Formato de saída (tabelas, seções, hierarquia)
 - **M**odality: Tom, regras, restrições

═══════════════════════════════════════════════
 ETAPA 3 — AUTOAVALIAÇÃO HONESTA
═══════════════════════════════════════════════
 Dê notas de 1-5 para cada critério:
 - Clareza (instruções inequívocas?)
 - Especificidade (detalhe suficiente?)
 - Completude (cobre todos os aspectos?)
 - Ação (é executável diretamente?)
 - Exemplos (few-shot embutido?)
 - Restrições (limites bem definidos?)
 - Fundamentação (tem base técnica/legal?)

 REGRA OBRIGATÓRIA: Pelo menos 1 critério deve ter nota <4. Justifique cada nota.
 PROIBIDO: Dar nota máxima em tudo sem ressalvas.

═══════════════════════════════════════════════
 ETAPA 4 — ITERAÇÃO COM MEMÓRIA (OPRO)
═══════════════════════════════════════════════
 Gere 2 versões adicionais do prompt, aplicando esta regra:
 - Mantenham trechos das versões anteriores com score >4 (preservar o que funciona)
 - Corrigir apenas os pontos fracos identificados
 - A cada versão, inclua um breve "changelog" do que mudou
 - Retorne a versão final (a melhor entre as 3)

═══════════════════════════════════════════════
 ETAPA 5 — EXEMPLOS FEW-SHOT
═══════════════════════════════════════════════
 Gere 1-2 exemplos de entrada → saída esperada usando o prompt final.
 Exemplos devem ser realistas e demonstrar o valor do prompt.

═══════════════════════════════════════════════
 ETAPA 6 — AUDITORIA DE ARMADILHAS
═══════════════════════════════════════════════
 Liste 3 pontos fracos que um avaliador crítico atacaria no prompt gerado.
 Em seguida, edite o prompt eliminando essas armadilhas.

═══════════════════════════════════════════════
 ETAPA 7 — VERIFICAÇÃO FINAL
═══════════════════════════════════════════════
 Auto-Score Final (1-5 por critério da Etapa 3), com justificativas.
 Calcule o Índice de Fidelidade: quão próximo o prompt final está do pedido original (0-100%).

 REGRAS GLOBAIS
═══════════════════════════════════════════════
 • Prompts gerados sempre em PT-BR
 • Linguagem técnica, ordem direta, sem redundância
 • Nunca inclua autoelogio no feedback ("excelente", "perfeito")
 • Zero tolerância para vaguidade — se algo é ambíguo, pergunte
 • Se o pedido do usuário é insuficiente, liste o que falta e preencha com premissas explicitadas
 • Use XML tags ou markdown para estruturar seções do prompt gerado
